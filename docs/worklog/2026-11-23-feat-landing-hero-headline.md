# 落地页 Hero 改为固定卖点标题 + 轮播副句

- 日期：2026-11-23
- 分支：main
- PR：
- 关键 commit：本条目所在提交

## 背景

黑鹰反馈落地页 hero 的卖点没有亮点。原来的标题是「TokenFunc，」加打字机轮播三条卖点（真模型不降智 / 内容不留存 / 账单逐条可对），任一时刻只露出三分之一的主张，访客前几秒抓不住重点。

要求：营销页要有冲击力，直接摆企业刚需卖点，用专业表达而不是技术术语（例如不写「请求响应不留存」）。

参考了 14 家同类产品的首屏：标题都不放数字；国内普遍在写「企业级 / 一站式 / 几折起」，没有一家把模型真实性和数据安全放进首屏标题。

## 变更

前端（`web/src/features/landing`）：

- 主标题改为固定文本「真模型 · 供应稳定 · 数据安全」，不再轮播，也不再带「TokenFunc，」前缀。
- 打字机降为标题下方一行绿色副句，轮播四条：高性能，低延迟 / 高缓存命中，成本更低 / 数据安全，内容不存档 / 对公开票，账单可对。
- 可视的打字区对读屏隐藏，另用一句 `sr-only` 完整句读出四条副句。
- 固定副标题的简体、繁体译文把「不存储你的请求与响应内容」改为「数据不存档」，英文 key 不变。
- 删除只为旧单行标题服务的 `use-hero-title-metrics` hook 及其测试。
- 7 个语言文件（`web/src/i18n/locales/tokenfunc/`）同步新增与删除对应 key。

文档：`docs/design/landing-v3-handoff.md` 的 Hero 章节、决策表、文案表、验收项同步。

## 验证

- `bunx vitest run src/features/landing`：6 个文件 24 个用例通过。
- `bun check -b`：无类型错误。
- `bunx oxlint src/features/landing`：无 error。
- `bun run i18n:sync`：通过。
- 本地 dev（5173）浏览器核对：
  - 中文标题在 1440 以上宽度单行、88px，无横向溢出；按 28px 实测标题宽 275px，小于 390 手机的可用宽度 350px。
  - 四条副句完整轮播一轮，打字区高度始终不变，回删时下方内容不跳动。
  - 英文标题 1440 单行，768 与 500 宽度折两行，无横向溢出（这一项是用上一版英文标题测的，现在的英文标题更短）。
- 没有做的：390 宽度的真实视口截图（浏览器窗口最小只能到 500）、浅色主题、减弱动效下的浏览器实测（减弱动效由 `typewriter.test.ts` 覆盖）。

## 遗留

- 「高性能，低延迟」「高缓存命中」是定性说法。运行质量区的具体数字（首 token 延迟、缓存命中率等）仍是未核实的占位，上线前要核实，否则首屏说法没有数据支撑。
- 「数据安全，内容不存档」：异步任务表与错误日志可能夹带内容，这两处例外上线前必须核完。
- 「供应稳定」只指多路供应与自动切换，SLA 不含上游原厂故障。
- 「对公开票」发版前需确认开票流程已就绪。
