## 注意事项

- ⚠️ **客户端识别规则两处缺口**（PR #20 自身规则，不影响计费 / 路由，只影响使用日志展示与统计）：
  - `client_platform` 只匹配 `macintosh` / `mac os x` / `darwin`，Codex CLI 的 UA 操作系统段形如 `Mac OS 15.6.1`（无 "x"），Mac 上的 Codex 请求平台列显示 unknown。冒烟用的 UA 是按 Codex CLI 的 os_info 输出伪造的，真实格式待生产出现真实 Codex 请求后 grep `client_user_agent` 核对。
  - Claude Code 的 UA `claude-cli/x.y.z (external, cli)` 没有来源规则，落 unknown。
  - 原始 UA 已完整落库，历史数据可事后重归类；建议等真实 Codex / Claude Code 请求核对 UA 格式后一次改准（加规则 + 测试用例）。
- 不存在的模型返回 503 `model_not_found` 是上游 distributor 既有行为，本版未改动该路径。
- 上版遗留待办未变：生产 `billing_setting.billing_expr` 的 DeepSeek 高峰时段（Asia/Shanghai 1-3 / 6-9 点）待核对；`/release-standalone` skill P6 的 `[GIN]` awk 对 JSON 日志无效，本次继续用 `grep '"type":"access"' | jq`，skill 文档待同步修正；生产 `compose.override.yml` 的 `CRITICAL_RATE_LIMIT=200` 待删。
