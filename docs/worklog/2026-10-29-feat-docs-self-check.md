# 文档中心改版二期：连接自检

- 日期：2026-10-29
- 分支：worktree-feat-docs-self-check
- PR：#72
- 关键 commit：4cf2ef88a

## 背景

一期（#71）补齐了教程，但普通用户在工具里配好后连不上时，很难判断问题出在哪：
- 地址里 `/v1` 多写了还是少写了；
- 密钥是否有效；
- 这把密钥能不能用所选的模型；
- 余额够不够；
- 有没有可用的渠道。

二期做「连接自检」：把这几类问题逐项查出来，并直接给出修复方法。

需求取舍（与黑鹰确认）：
- 第 4 步发一次真实请求，会扣极少余额，点击按钮前有提示。
- 只用用户的默认密钥（名为 default 的启用密钥，没有则取最近创建的一把）。未登录的用户只看到登录入口，不能粘贴密钥。

## 变更

- 「开始使用」分组新增「连接自检」页（`self-check`），正文由 `:::self-check` 组件渲染。
- 检查逻辑在 `lib/self-check.ts`，都是纯函数：
  - 13 个工具档案：每个工具用的协议、地址要不要带 `/v1`、默认模型系列、对应教程。
  - `checkAddress`：比对用户在工具里填的地址，识别以下问题：多了 `/v1`、少了 `/v1`、填成了完整接口路径、不是本站、http/https 不一致、路径不对。
  - `classifyFailure`：把网关返回的状态码和错误码归类，归类结果决定给用户的修复建议。
  - `buildProbeRequest`：按工具使用的协议构造最小请求。Messages 与 Chat 用 `max_tokens=1`；Responses 用 `max_output_tokens=16`，这是该接口的下限。
- 组件 `connection-check.tsx`：选择工具、填地址、选模型，然后依次执行四步：
  1. 地址写法
  2. 用 `GET /v1/models` 检查连通性和密钥
  3. 模型权限：不可用时列出这把密钥能用的模型
  4. 一次真实调用
- 每步失败都给出原因、改法，并链接到对应的工具教程。
- 请求直接用 `fetch` 发给网关，不走控制台的 api 实例。原因是那个实例的 401 拦截器会把模型接口返回的 401 误判成登录失效。
- 默认密钥的逻辑从示例参数栏抽成 `hooks/use-docs-sample-key.ts`，供示例参数栏和自检共用。取密钥明文的请求按 store 里的 `requestedKeyId` 去重，两个组件同时挂载时只请求一次。
- 入口：
  - 每篇工具教程顶部加入「配置后还是连不上？」入口，链接带 `?tool=` 预选当前工具。
  - FAQ 开头和「选择接入方式」页也加了链接。
- 新增 36 条界面文案，补齐 7 种语言。

## 遗留

- 检查用的是默认密钥。用户在工具里填了另一把密钥时，自检只能证明本站与模型正常，页面上已有说明。
- 下拉框里的模型来自用户分组下的可用模型，可能和这把密钥的模型限制不一致；不一致时由第 3 步提示。
- 三期：Scalar API 参考与在线调试，并补齐 embeddings、rerank、音频等接口。
